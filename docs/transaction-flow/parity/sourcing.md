## Summary (10 lines)

1. **Current behaviour:** a Stripe `payment_intent.succeeded` on a $99 deposit creates the auction inside the money txn, then **immediately** `launchAuction` + `inviteDealersToAuction` (`app/api/webhooks/stripe/route.ts:259-265`). There is no sourcing case; the spec's "settlement opens a sourcing case, auction launches only when field is ready" is **MISSING**.
2. **Who is invited:** only registered `Dealer` rows (`status:"ACTIVE", isSystemPlaceholder:false`, `dealer-invitation.service.ts:285-288`), geo-filtered by haversine from buyer coords (`:313`), scored (`:42-79`), top **8** (`:16`, `:324-327`). Outside dealers (`OutsideAuctionInvite`/`DealerRooftop`) are invited **only** by an admin (`launch-auction` / `invite-outside-dealers`), never by the automatic path.
3. **Radius:** ladder is `RADIUS_TIERS = [25, 50, 100, 150]` (`coverage.service.ts:38`), stop when ≥8 registered (`dealer-invitation.service.ts:256-261`); city-only buyers use flat 150 (`:21`). No 100/150/250 bands, no buyer-authorized >250. Radius is **not** client-controllable on any auction/sourcing route (only catalogue search/`public/inventory` accept `radiusMiles`, a display filter) — the server-side rule is ALREADY CORRECT in spirit but the ladder values are wrong.
4. **Null-location predicate:** `dealer-invitation.service.ts:245-250` derives coords from `zip`→`geocodeZip`, else `city+state`→`lookupCity`; `:263-282` returns `0` (fail closed, audit row `AUCTION_ZERO_INVITATIONS`). Deliberate, tested (`__tests__/dealer-invitation.test.ts:224`). Preserve.
5. **dc009660 early close:** `deposit-activation-reconcile` cron (`*/5`, `vercel.json`) → `reconcileStuckActivations` (ACTIVE + zero invitations older than `ACTIVATION_GRACE_MINUTES=5`) → `classifyActivation` returns `'invite'` (re-runs matcher → 0 again) until `auctionAgeMinutes >= noDealerCloseGraceMinutes`, then `'close'` (`deposit-activation-policy.ts:35-40`). The injected value is **`NO_DEALER_CLOSE_GRACE_MINUTES = 120`** (`deposit-activation.service.ts:56`, injected `:150`). 19:35 → 21:35 = exactly 120 min. Close is `updateMany ACTIVE→CLOSED` (`:234-237`) + ops `SYSTEM_ALERT` (`:91-97`); deposit retained (no auto-refund).
6. **Thresholds (§6c):** none of 5–8 auto / >8 best-8 / 3–4 limited+audited / 1–2 continue / 0 close-after-review exist as a decision table. Today: whatever the matcher returns (0..8) launches; 0 converges to a 120-min close with no Ops review gate.
7. **Launch readiness (§7 entry):** MISSING as a checklist. `launchAuction` is unconditional; the admin launch route even mints a `PAID` deposit with no Stripe intent (`launch-auction/route.ts:139-144`). `charge.dispute.created` is audit-logged only (`stripe/route.ts:769-795`) — "undisputed" is not a gate anywhere.
8. **Invitations:** registered dealers get an `AuctionInvitation` with **no token, no expiry, no delivery state** (schema `:518-531`) and a generic `/dealer/opportunities` link (`dealer-invitation.service.ts:401`). Outside dealers get a plaintext-uuid token with `expiresAt` (schema `:467,477`); only `DealerInvitation` (recruitment) tokens are hashed (migration `20260828000000_dealer_invitation_token_hash`). Reminders: QStash +24h/+42h (`jobs/dealer-invited:42`, `dealer-bid-reminder:50`) or cron 5–7h-before (`cron/dealer-invitation-reminder:19-20`); outside invites get no reminder. Bounce → suppression only; no contact-replacement exception.
9. **Identity firewall (§25.1):** the invite email and dealer auction view carry no buyer identity (ALREADY CORRECT; `dealer-invitation-pii.test.ts`), but `identity_firewall_entries` has **zero readers or writers** anywhere in the repo, and the winner email releases first name + last initial at award (`notifications/dealer-award.ts:28`) — before any "reaffirmation" (no reaffirmation model/route exists).
10. **Anti-circumvention (§25.2):** pattern matching exists only for **buyer→support** messages (`messaging.service.ts:6-45`, used by `app/api/buyer/messages`); the dealer message route writes `prisma.message` directly with `isRedacted:false` (`app/api/dealer/messages/route.ts:78-84`) — dealer→buyer messages are **not monitored**. `circumvention_attempts` is never written (`recordCircumventionAttempt` has no callers). No scorecard/suspension consequence is wired.
