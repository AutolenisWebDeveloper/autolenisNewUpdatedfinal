## Summary (10 lines)

1. The **$99 money-cluster is solid**: signature-verified webhook, `PaymentProviderEvent` claim inside the same `$transaction` as the `PENDING→PAID` flip (`app/api/webhooks/stripe/route.ts:162-229`), DB-enforced transition matrix (`lib/payments/deposit-state.ts:16-21`), provider-side duplicate-charge guard via one shared rule (`classifyPaymentConfirmation`), idempotency-keyed refunds, no auto-refund anywhere. Preserve all of it.
2. **Deposit → auction, not deposit → Vehicle Request.** `Deposit` has no `vehicleRequestId` (`prisma/schema.prisma:401-415`); the PaymentIntent is keyed per buyer per UTC day (`create-intent/route.ts:224`); a second PAID deposit is refused (`:93-95`). "One intent per Vehicle Request", `PAYMENT_REQUIRED`, and "open the sourcing case" are all **MISSING**; "new request = new $99" is structurally impossible today.
3. **Eligibility recheck (§5a) is partial**: prequal + shortlist + rate-limit only. No onboarding, geocoded-location, criteria, co-buyer/trade, conflicting-request or disclosure-acceptance check — the location gap is the proven root cause of paid-but-zero-invitation auctions (`docs/plans/BUYER-LOCATION-GAP.md`).
4. **Disclosures (§5b) are mostly absent** and the framing contradicts the spec: the UI sells a "refundable Auction Access Deposit" / "Free to start" Standard plan, not "the Standard plan, paid in full".
5. **Six-touch reminder cadence is built and tested** (0/1h/6h/24h/72h/day-7, `lifecycle-touch-drain.service.ts:155-247`); message content lacks the VR reference/summary/support contact; cancellation on VR cancel/closure is not wired; and **three legacy reminder implementations still exist** (DUPLICATED).
6. **Reconciler exists, settlement stage off by default** (`DEPOSIT_SETTLEMENT_RECONCILE_ENABLED==="true"`), alerts via `SYSTEM_ALERT`; but it carries a hardcoded production deposit id in source and its settle path skips the receipt/reminder-cancel/analytics tail the webhook runs.
7. **Refunds**: manual-only holds, but `RefundReason` enum is defined and used nowhere; three deposit-refund implementations coexist; the concierge-fee refund route can label a no-charge fee as refunded; **cancel actions auto-refund** (`DEAL_CANCELLED`, `AUCTION_REFUND_TRIGGERED`) — violating "cancellation and refund are separate decisions".
8. **Premium is a free flag flip today** (`app/api/buyer/plan/upgrade/route.ts:12-16`) with no window, no $400 at upgrade, no concierge assignment, no ownership move, no plan snapshot, no touchpoint sequence, no suppression guardrails, and entitlement before settlement. §23.2/23.2a/23.2b/23.3 are largely MISSING.
9. **$400 math** (`PREMIUM_FEE_CENTS − DEPOSIT_AMOUNT_CENTS`) is correct and `service_fee_payments` records gross/credit/net — but the $99 credit is granted unconditionally (refunded/charged-back $99 still credited), and one admin report computes fee revenue from `buyer.plan` (BROKEN vs §23.5).
10. **Commissions** are created at fee payment (not Deal completion), reversed only on *fee* refund; $99 refund/chargeback and Deal cancellation reverse nothing (commission rule text lives in §6.5/§22.1).

## Stronger safeguards to preserve

- Webhook: raw-body signature verification; missing secret → 500; invalid signature → 400 + `recordWebhookRejection` (`stripe/route.ts:58-115`).
- `PaymentProviderEvent` claim **inside** the deposit `$transaction` with bounded `maxWait/timeout`; replay = duplicate ack; crash rolls back the claim (tests `stripe-idempotency.test.ts:193-246`).
- DB-enforced deposit transition matrix via `allowedPredecessors` in every status write (webhook, reconciler, refunds); late success never resurrects REFUNDED; late failure never downgrades PAID.
- One shared "buyer has been charged" rule (`classifyPaymentConfirmation`) used by create-intent, fee service, success pages, reconciler; `CHARGE_UNSETTLED` 409 never renders a card form.

- Concierge track isolation: reconciler refuses to create a competitive auction unless `metadata.type === "deposit"` (fail-closed on unknown/provider outage).
- Settlement reconciler: strict `"true"` opt-in; exclusion list applied in the query; never fabricates a `PaymentProviderEvent`; alerts on every settle.
- Activation reconciler: per-deposit idempotency guard; atomic PENDING→launch claim; ACTIVE→CLOSED atomic; invite only when zero invitations (load-safe).
- Unroutable payment → deduped `SYSTEM_ALERT` (never a bare 200).
- Reminder chain: single enroller; `UNIQUE(base_key, sequence)`; send-time guard authoritative; TCPA/DNC/suppression gating in `notifyContact`; concierge buyers excluded.
- Commissions: ≤3 levels, idempotent on `qualifyingEventId`, basis = captured amount, PAID never auto-reversed, approval cron fails closed on unverifiable Stripe state, DLQ replay of the walk.
- Admin money actions: role allow-lists / `requirePermissionStrict`, mandatory reason, `AdminAuditLog` with `providerConfirmed:false` on overrides.
