## Summary (10 lines)

1. The canonical auction offer (`Offer`, `prisma/schema.prisma:533-572`) carries only money + financing fields (`otdPriceCents, vehiclePriceCents, taxCents, feesCents, junkFeeItems, includesFinancing, aprRate, termMonths, aprFlag, version, originalOfferId, submittedAt, externalDealer*, notes, submittedByAdminId`). Every §8a vehicle/disclosure field (VIN, stock #, colors, availability, discounts, doc fee, title/reg, add-ons, delivery, out-of-state registration, condition/history/photos, expiration, feature match, sale confirmation) is MISSING from the auction offer; some exist only on the legacy concierge `DealerOfferSubmission.vehicles` JSON.
2. §8b validation is PARTIAL: arithmetic (±1¢), financing consistency, one-live-offer-per-dealer-per-auction, invitation gating, and APR>29 flag are real (`lib/services/offer/offer.service.ts`, `otd.ts`); the approved-budget check ignores `decision`/`expiresAt` and silently passes when no prequal exists; no VIN/criteria match, no candidate binding, no per-rooftop 3-cap, no required-field check for disclosures; the admin `POST /api/admin/offers` bypasses every validation and the Serializable one-live-offer guard.
3. Junk-fee handling is BROKEN in units: `otd.ts:72-75` treats `junkFeeItems[].amount` as dollars, `best-price.service.ts:64-65` sums the same values as cents, and the admin route stores `{label, amount}` instead of `{name, amount}`. `JunkFeePattern` / `detectJunkFees` are never consulted on the auction path (no callers).
4. §8c auction operation is largely ALREADY CORRECT: dealer isolation (`app/api/dealer/auctions/[auctionId]/route.ts`), revisions retained as new rows (`WITHDRAWN` original, max 1), anti-snipe 5-min/6-cap atomic (`anti-snipe.service.ts`), atomic F-001 post-close claim + release-on-failure + cron reconciler (`auction.service.ts:118-216`, `app/api/cron/auction-close/route.ts:33-44`).
5. Ranking is PARTIAL/DUPLICATED: the engine ranks OTD/monthly/junk with persisted weights and a log at close, but there is no vehicle-match, mileage, distance, expiration, or market-price dimension, no cross-candidate mode, and no deterministic tie-break (ties resolve by array order). The buyer GET route (`app/api/buyer/auctions/[auctionId]/best-price/route.ts`) recomputes Best Cash/Best Monthly itself with a fabricated 7% APR default and never logs, so what the buyer sees is not the logged ranking.
6. Zero-offer branch: buyer notice + dealer no-winner emails exist; no owned Ops case, no one-time relaunch path (`Auction.originalAuctionId` has no writer; admin `AUCTION_REOPENED` sets a status that `submitOffer` rejects), no pre-close trending-to-zero alert (only a post-hoc 24h funnel counter and a no-dealer activation exception). `VehicleRequestStatus.OFFER_READY` has no writer anywhere.
7. 8. Deal lineage is PARTIAL: `commitOfferSelection` writes only `buyerId, offerId, status=FINANCING_PENDING` (`select-offer.service.ts:53-55`); auction/deposit/vehicleRequest/dealer are reachable only through `offer`; no VIN, vehicle snapshot, OTD snapshot, co-buyer, trade, rooftop, plan snapshot, no `DealStatusHistory` row at creation, and the status is `FINANCING_PENDING` (no `DEALER_CONFIRMATION` state exists).
9. Premium invitation (§9a) is MISSING entirely: no full-screen invitation, no 1-hour follow-up, no suppression flags; the only mentions are the free `POST /api/buyer/plan/upgrade` and a "Concierge Fee" step in the deal-selected email. 10. Three offer models coexist (DUPLICATED): canonical `Offer`; legacy concierge `VehicleOffer → DealerOfferSubmission → BuyerOfferReview(Item)` (converges to canonical only via the Stripe `concierge_deposit` webhook); and `VehicleRequestOffer` (admin-sent single offer creating a `Deal` with `vehicleRequestOfferId`, bypassing the auction lock). ## Stronger safeguards to preserve

- Serializable one-live-offer txn + invitation gate + ACTIVE/endsAt checks (`offer.service.ts:87-133`).
- OTD ±1¢ reconciliation with negative-item rejection, shared by concierge conversion (`otd.ts`).
- Single revision cap (`MAX_OFFER_REVISIONS = 1`) and `originalOfferId @unique`.
- Anti-snipe atomic exact-`endsAt` guard; concurrent bids extend at most once.
- F-001 claim/release + bounded reconciler; concierge auctions pre-stamped.
- `SELECT … FOR UPDATE` selection with re-check; `Deal.offerId @unique`; `forceEarly` audited early accept; cancelled-auction rejection.
- No auto-refund anywhere at close/decline; admin refund only with zero SUBMITTED offers and only for a real charge.
- Dealer anonymisation: budget bucketed to $5k, `buyerId` stripped, medians only at n≥4/5, winners receive first name + last initial only.
- Outside-dealer route recomputes OTD server-side, single-use atomic invite claim, rate limited.
- Dealer-award dispatch: durable marker, bounded retries, per-recipient isolation, idempotent email keys and in-app dedupe.
- Best-price log written only by terminal callers (close, admin run) — avoids unbounded log growth.
